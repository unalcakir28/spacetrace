# Packaging

Four package managers, one renderer. The templates here are checked in with
`@PLACEHOLDER@` markers; `render.sh` fills them from a published release and
writes the results into `packaging/dist/`, which is not checked in.

Nothing here is built from the working tree. Every manifest points at a
**published release asset** and carries its SHA-256, so rendering one for a
version that was never published fails rather than producing a manifest that
404s for the first person who installs it.

```bash
./packaging/render.sh v0.9.0
ls packaging/dist/
```

## Why this exists

As of 22 September 2026 spacetrace is in **no package manager at all**. Every
install goes through `install.sh` or a manual download, which is the step most
people never take: 121 downloads across 14 releases. The tools it is measured
against are all one command away — `brew install dua-cli`, `scoop install
gdu`, `pacman -S ncdu`. Being faster than them is invisible to someone who
cannot install it the way they install everything else.

## The layout trap

The archives are not shaped the same way, and a manifest that assumes they are
installs nothing:

| Asset | Binaries live at |
|---|---|
| `*-apple-darwin.tar.gz` | the archive root — `./spacetrace` |
| `*-linux-musl.tar.gz` | the archive root — `./spacetrace` |
| `*-pc-windows-msvc.zip` | a versioned subdirectory — `spacetrace-v0.9.0-x86_64-pc-windows-msvc/spacetrace.exe` |

So Scoop needs `extract_dir` and winget needs a `RelativeFilePath` with the
version in it, while Homebrew and the AUR package install straight from the
root. Both binaries ship in every archive: `spacetrace` and `spacetrace-agent`.

## One-time setup, per manager

None of this is automatic the first time. Each of these is a repository or an
account that has to exist before any workflow can push to it.

### Homebrew — `unalcakir28/homebrew-tap`

A tap is an ordinary public repository whose name starts with `homebrew-`.
Create it, put the rendered formula at `Formula/spacetrace.rb`, and from then
on the install is:

```bash
brew install unalcakir28/tap/spacetrace
```

A formula in `homebrew-core` instead would remove the tap prefix, but it
requires the project to be notable enough for their acceptance criteria — 0
stars does not clear it. Revisit.

### Scoop — `unalcakir28/scoop-bucket`

Same idea: a public repository holding `bucket/spacetrace.json`.

```bash
scoop bucket add spacetrace https://github.com/unalcakir28/scoop-bucket
scoop install spacetrace
```

The manifest carries `checkver` and `autoupdate`, so once the bucket exists
Scoop's own bot can follow new releases without a push from here.

### winget — a pull request to `microsoft/winget-pkgs`

There is no repository to own; each version is a pull request adding three
YAML files under `manifests/u/unalcakir28/spacetrace/<version>/`. They are
validated by a bot and merged by a maintainer, so a release reaches winget
hours or days after it reaches GitHub, not minutes.

### AUR — `spacetrace-bin`

An SSH key registered with aur.archlinux.org, then a git push of `PKGBUILD`
and `.SRCINFO` to `ssh://aur@aur.archlinux.org/spacetrace-bin.git`.
`.SRCINFO` is generated by `makepkg --printsrcinfo`, which needs an Arch
machine or a container — `render.sh` writes the `PKGBUILD` and leaves that
step to whoever has one.

## Deliberately not here

- **Flathub.** A desktop-app store for a command-line tool, and the sandbox is
  the wrong shape for something whose whole job is reading the filesystem.
- **`cargo install`.** It works today and needs nothing from this directory,
  but it compiles from source and reaches only people who already have Rust.
- **Debian and Fedora archives.** Their processes take months and want a
  maintainer who is not the author. Revisit when there is someone to ask.
