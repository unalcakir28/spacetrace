Every disk analyser tells you what is on the disk. This one tells you what changed.

Scan a disk, keep the result as a snapshot, and compare two snapshots to see which folder actually grew — here, on a server you never log in to, or across a fleet that reports its own fill-up date.

Download for your machine
curl -fsSL https://raw.githubusercontent.com/unalcakir28/spacetrace/main/install.sh | sh

Installs the CLI and the agent into /usr/local/bin. Deliberately boring POSIX sh, because it also has to run on NAS firmware whose shell is busybox.

Question one is solved. Question two is not.

TreeSize, WizTree, DaisyDisk, FreeSize, ncdu, du — they are good tools and they all answer the same question: what is on the disk in front of me right now?

The question that actually wakes people up is the second one: what changed since last week, and on which machine? Answering it needs three things a live scan cannot give you — a record of the past, a comparison that points at a culprit rather than a root, and the same tool running somewhere you are not sitting.

That is the whole idea. Everything below is in service of it.

Three parts, one core

The scanner, the snapshot store, the diff and the treemap layout are one Rust library. The three things you can install are windows onto it, which is why a snapshot taken in one is readable by the others.

CLI and agent Apache-2.0

spacetrace · spacetrace-agent

The command line tool, and the same code as a service that scans on a schedule and answers over HTTP. One static binary with no runtime to install.

  • Scan, store snapshots, diff, list, export to ncdu
  • Point any read-only command at a remote agent
  • Runs on a NAS, in a container, on old glibc
  • The agent reads. It never deletes anything.

What the app does

Hub Proprietary

self-hosted · one binary, one SQLite file

Agents push their snapshots to it. It keeps the history, works out what is growing, and tells you before a disk fills up.

  • Fleet dashboard ordered by urgency, not by name
  • Growth rate and a “fills in N days” forecast
  • Threshold rules with webhook delivery
  • Never touches the machines it watches

Colour is the reading, not the decoration

On a map of land cover the colours are the information. The same is true of file types, so the palette runs through the whole window — the map, the folder list and the inspector — and a category means one colour everywhere.

Sizes read as on disk by default. A sparse Docker.raw claims a terabyte and holds nineteen gigabytes, and drawn from its claim it would take 99% of the map and turn everything genuinely large into a sliver.

Numbers you can check, and silence where you cannot

A disk tool that prints a figure you cannot reconcile with du has lost the argument. These are test conditions in the repository, not aspirations.

  • Totals match du exactly

    Logical is file bytes only and matches du -sb. On disk is the blocks actually allocated, directory blocks included, and matches du -s --block-size=1. Verified on /usr (141k files), /usr/share and /etc.

  • Free of total, never “% used”

    Filesystem capacity is reported the way df reports it. On an APFS container, a btrfs subvolume or thin LVM, a “used” figure includes the siblings and disagrees with df about the same mount — so it is not printed.

  • The forecast is withheld more often than it is shown

    “Fills in N days” appears only with at least three snapshots spanning a day, a linear fit of r² ≥ 0.5, a capacity that was actually measured, and an answer inside ten years. A log rotation will happily produce a fitted line whose slope means nothing, and a confident wrong date is worse than no date.

    When a condition fails the column is blank and the page says which one.

  • A snapshot is a plain SQLite file

    Not an export format, not a proprietary blob. What the agent stores is what travels over the wire and what lands on your laptop, so listing, browsing and diffing a remote snapshot runs the identical code as a local one. spacetrace export also writes ncdu's format if you would rather use that.

  • Errors are counted, not swallowed

    An unreadable path is reported and sampled; the scan carries on. A cancelled scan returns no tree at all, because a partial tree looks complete and reports a total that was never true of any disk.

  • The agent has no delete

    Software you are asked to install on a server earns trust by not being able to do the frightening thing. This is a decision, not a missing feature. The desktop app can move entries to the Trash — only ever on a live scan of the machine you are sitting at, and only after asking.
